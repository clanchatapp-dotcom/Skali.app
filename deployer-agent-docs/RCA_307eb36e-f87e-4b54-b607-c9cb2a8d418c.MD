# RCA — birthday-picker-1 (run 307eb36e-f87e-4b54-b607-c9cb2a8d418c)

## Symptom
Deploy failed at **build_image** (Cloud Build), frontend-build stage 13/14. Vite exited in ~10ms:

```
$ cd .. && ([ -e node_modules ] || ln -s frontend/node_modules node_modules) && vite build --outDir frontend/build --emptyOutDir
vite v5.4.21 building for production...
✓ 0 modules transformed.
x Build failed in 10ms
error during build:
Could not resolve entry module "index.html".
```

## Root cause (source, not infra/manifest)
The farm template builds the frontend by copying **only** `frontend/` into the image (`COPY frontend/ /app/` in `Dockerfile.cloudbuild`), then runs `yarn build` with cwd `/app`.

But `frontend/package.json`'s build script is written for a monorepo layout:

```json
"build": "cd .. && ([ -e node_modules ] || ln -s frontend/node_modules node_modules) && vite build --outDir frontend/build --emptyOutDir"
```

`cd ..` moves from `/app` to `/`, which in the container has **no `index.html`** (only `frontend/`'s contents were copied in). Vite's root becomes `/`, finds no entry module → "Could not resolve entry module index.html", 0 modules transformed. The `--outDir frontend/build` path is also wrong in-container (would write to `/frontend/build`, not the `/app/build` the Dockerfile later looks for).

In preview this "works" only because the repo root happens to contain a *second, stale* Vite app (`/index.html`, `/src`, `/vite.config.ts`) — but that root app is NOT the one the dev server runs, and it is never shipped to the deployment image. The real, current app is self-contained in `frontend/` (`frontend/index.html`, `frontend/vite.config.ts`, `frontend/src/main.tsx` — the same files the dev server (`vite` run from `frontend/`) uses).

## Fix (apply in source — E1)
In **`frontend/package.json`**, change the `build` script to build in place:

```json
"build": "vite build --outDir build --emptyOutDir"
```

This uses `frontend/index.html` as the entry, builds the self-contained frontend app, and writes to `frontend/build` (= `/app/build` in-container), which the farm `Dockerfile.cloudbuild` picks up via `if [ -d "build" ]`.

(The stale root-level Vite app — `/index.html`, `/src`, `/vite.config.ts` at repo root — is unused by deployment and can be ignored/removed separately; it is not required for the fix.)

## Verification
In the eph sandbox I replaced the build script with the fixed one and ran `yarn install` against `frontend/` — it completed cleanly (`Done in 75.65s`, exit 0). The full `vite build` could not be run to completion in the sandbox because the Vite build of this large app exceeds the sandbox's memory ceiling (pod OOM/137). This is a **sandbox limitation only** — the production failure was an instant entry-module-resolution error (10ms), not an OOM, and Cloud Build has ample memory. The fix directly removes the `cd ..` that caused the reported failure.
